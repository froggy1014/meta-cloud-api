`meta-cloud-api/testing` lets you test a bot end to end without a Meta app, a phone number or network access. It ships with the SDK (nothing extra to install) and gives you:

| Helper | What it does |
| --- | --- |
| `createTextMessageWebhook()` and friends | Build the exact webhook JSON Meta posts, typed with the SDK's own webhook types |
| `createSignedWebhookRequest()` | Wrap a payload in a `Request` with a valid `X-Hub-Signature-256` |
| `createFlowRequest()` / `decryptFlowResponse()` | Encrypt a Flow endpoint request the way Meta does and read the encrypted reply |
| `createMockCloudApi()` | An in-memory Graph API: records every request the SDK sends and answers with realistic responses or Meta errors |

Everything uses Web APIs only (`fetch`, `Request`, Web Crypto), so the helpers run on Node.js, Bun, Deno and Cloudflare Workers, under Vitest, Jest, `node:test` or `bun test`.

## A complete bot test

Say your bot replies to every text message. This test delivers a signed webhook to it and checks what the bot sent back, with no mocks of your own (the bot is inlined here; in a project it lives in its own module):

```typescript
// src/bot.test.ts
import { WebhookProcessor } from 'meta-cloud-api';
import { afterEach, beforeEach, expect, it } from 'vitest';
import {
    createMockCloudApi,
    createSignedWebhookRequest,
    createTextMessageWebhook,
    type MockCloudApi,
} from 'meta-cloud-api/testing';

// The bot under test (normally imported from src/bot.ts)
function createBot(config: { accessToken: string; phoneNumberId: number; appSecret: string }) {
    const processor = new WebhookProcessor({ ...config, verifyWebhookSignature: true });

    processor.onText(async (whatsapp, { message }) => {
        await whatsapp.messages.text({ to: message.from, body: `You said: ${message.text.body}` });
    });

    return processor;
}

const APP_SECRET = 'test-app-secret';
let api: MockCloudApi;

beforeEach(() => {
    api = createMockCloudApi().install(); // routes the SDK's fetch calls to the mock
});

afterEach(() => {
    api.restore(); // puts the real fetch back
});

it('echoes text messages', async () => {
    const bot = createBot({ accessToken: 'test-token', phoneNumberId: 1234567890, appSecret: APP_SECRET });

    const request = await createSignedWebhookRequest(
        createTextMessageWebhook({ from: '15551234567', text: 'hello' }),
        { appSecret: APP_SECRET },
    );
    const response = await bot.processWebhook(request);

    expect(response.status).toBe(200);
    expect(api.sentMessages()).toEqual([
        expect.objectContaining({ to: '15551234567', type: 'text', text: expect.objectContaining({ body: 'You said: hello' }) }),
    ]);
});
```

<Aside type="tip">
`WebhookProcessor` catches errors thrown by your handlers so that Meta does not retry the webhook. Assert on what the handler did (messages sent, state written) rather than on the webhook response alone.
</Aside>

## Webhook payload factories

Each factory returns a payload typed with the SDK's webhook types (`WebhookPayload`, `TextMessage`, `StatusWebhook`, ...), so a field typo is a compile error and the result can be passed anywhere the SDK expects a `WebhookPayload`.

| Factory | Dispatched to | Required options |
| --- | --- | --- |
| `createTextMessageWebhook` | `onText` | `from`, `text` |
| `createImageMessageWebhook` | `onImage` | `from` (`mediaId`, `mimeType`, `caption`, `sha256`, `url` optional) |
| `createButtonReplyWebhook` | `onInteractive` (`button_reply`) | `from`, `buttonId`, `title` |
| `createListReplyWebhook` | `onInteractive` (`list_reply`) | `from`, `rowId`, `title` |
| `createReactionWebhook` | `onReaction` | `from`, `messageId` (leave `emoji` out to remove a reaction) |
| `createLocationWebhook` | `onLocation` | `from`, `latitude`, `longitude` |
| `createStatusWebhook` | `onStatus` | `status` (`sent`, `delivered`, `read`, `failed`), `recipientId` |
| `createMessageWebhook` | by `message.type` | any message object (video, document, order, ...) |
| `createWebhookPayload` | the field's handler | a field name and its value |

Every message factory also accepts `profileName`, `id` (defaults to a random `wamid.`), `timestamp` (a `Date` or Unix seconds; defaults to now) and the business side: `phoneNumberId`, `displayPhoneNumber` and `wabaId`. Defaults are exported as `TEST_PHONE_NUMBER_ID`, `TEST_DISPLAY_PHONE_NUMBER` and `TEST_WABA_ID`.

```typescript
import {
    createButtonReplyWebhook,
    createStatusWebhook,
    createWebhookPayload,
} from 'meta-cloud-api/testing';

// The customer tapped "Yes" on the buttons you sent in wamid.question
createButtonReplyWebhook({ from: '15551234567', buttonId: 'yes', title: 'Yes', contextMessageId: 'wamid.question' });

// Your message failed (error 131026 is filled in unless you pass `errors`)
createStatusWebhook({ status: 'failed', recipientId: '15551234567', messageId: 'wamid.sent' });

// Any other webhook field, value typed by the field name
createWebhookPayload('account_update', { event: 'VERIFIED_ACCOUNT' });
createWebhookPayload('message_template_status_update', {
    event: 'APPROVED',
    message_template_id: 1234,
    message_template_name: 'order_update',
    message_template_language: 'en_US',
    reason: 'NONE',
});
```

Pull the message back out with full types:

```typescript
import { createTextMessageWebhook } from 'meta-cloud-api/testing';

const payload = createTextMessageWebhook({ from: '15551234567', text: 'hi' });
const message = payload.entry[0]?.changes[0]?.value.messages[0]; // TextMessage | undefined
```

## Signed webhook requests

`createSignedWebhookRequest(payload, { appSecret, url?, headers? })` returns a web `Request` signed with HMAC-SHA256 of the exact body, as Meta signs it. Use it with `verifyWebhookSignature: true` so your tests cover the production configuration. Pass a string to sign a body byte for byte, and `headers` to override the defaults (for example to test a bad signature).

The same request works with the framework adapters:

```typescript
import { nextjsAppWebhookHandler } from 'meta-cloud-api';
import { createSignedWebhookRequest, createTextMessageWebhook } from 'meta-cloud-api/testing';

const webhook = nextjsAppWebhookHandler({ accessToken: 'test-token', phoneNumberId: 1, appSecret: 'secret', verifyWebhookSignature: true });
webhook.processor.onText(async () => {
    /* ... */
});

const response = await webhook.POST(
    await createSignedWebhookRequest(createTextMessageWebhook({ from: '15551234567', text: 'hi' }), { appSecret: 'secret' }),
);
```

For Express, send the same body and `x-hub-signature-256` header with `supertest` (read them with `await request.text()` and `request.headers.get('x-hub-signature-256')`).

## WhatsApp Flows

`createFlowRequest(body, { publicKey, appSecret?, url? })` encrypts a Flow endpoint request like Meta does (AES-128-GCM for the data, RSA-OAEP SHA-256 with your public key for the AES key) and signs it. The result carries the `request` and the keys needed to read the reply. `generateFlowKeyPair()` makes a throwaway key pair with Web Crypto; keys from `generateEncryption()` work as well.

```typescript
import { FlowTypeEnum, WebhookProcessor } from 'meta-cloud-api';
import { createFlowRequest, generateFlowKeyPair } from 'meta-cloud-api/testing';
import { expect, it } from 'vitest';

it('answers the START screen', async () => {
    const keys = await generateFlowKeyPair();
    const processor = new WebhookProcessor({
        accessToken: 'test-token',
        phoneNumberId: 1,
        appSecret: 'secret',
        privatePem: keys.privatePem,
    });
    processor.onFlow(FlowTypeEnum.Change, (_wa, request) => ({
        screen: 'CONFIRM',
        data: { name: request.data?.name },
    }));

    // action defaults to 'data_exchange', version to '3.0'
    const flow = await createFlowRequest(
        { screen: 'START', data: { name: 'Ada' } },
        { publicKey: keys.publicPem, appSecret: 'secret' },
    );
    const response = await processor.processFlow(flow.request);

    expect(await flow.decryptResponse(response)).toEqual({ screen: 'CONFIRM', data: { name: 'Ada' } });
});
```

`{ action: 'ping' }` tests the health check. `decryptFlowResponse(response, keys)` is the standalone form of `flow.decryptResponse`; it accepts a string, the `processFlow()` result or a fetch `Response`, and parses plain JSON replies (error acknowledgements) as is.

## Mock Graph API

`createMockCloudApi(options?)` returns a `MockCloudApi`. `install()` replaces `globalThis.fetch` (the SDK sends every request through it), `restore()` puts the previous one back, and `mock.fetch` is available for code that takes a fetch function. Requests to other hosts pass through to the real fetch.

### Default responses

| Request | Response |
| --- | --- |
| `POST /{PHONE_NUMBER_ID}/messages` | `{ messaging_product, contacts: [{ input, wa_id }], messages: [{ id: 'wamid.…' }] }` (`{ success: true }` for read receipts and typing indicators) |
| `POST /{PHONE_NUMBER_ID}/media` | `{ id }`; the file is kept in `mock.media` |
| `GET /{MEDIA_ID}` | Media info with a lookaside `url`, `mime_type`, `sha256` and `file_size` of the uploaded file |
| `GET` the media `url` | The uploaded bytes |
| `DELETE /{MEDIA_ID}` | `{ success: true }` |
| `GET /{WABA_ID}/message_templates` | `options.templates` (default: an approved `hello_world`), filtered by `name`, `status`, `language`, `category`, `limit` |
| `POST /{WABA_ID}/message_templates` | `{ id, status: 'PENDING', category }` |
| Anything else | A Meta error (code 100) naming the route to add, so the SDK throws. Pass `{ unhandled: 'success' }` to reply `{ success: true }` instead |

### Inspecting requests

```typescript
import { createMockCloudApi } from 'meta-cloud-api/testing';

const api = createMockCloudApi().install();

api.requests; // every Graph API request: method, path (no API version), apiVersion, query, headers, bodyType, body
api.sentMessages(); // parsed message payloads, read receipts left out
api.sentMessages('interactive'); // filtered by type
api.lastSentMessage();
api.requestsTo('POST', '/:phoneNumberId/media'); // multipart bodies keep their File
api.reset(); // forget requests, media and custom routes
```

### Custom routes

`mock.on(method, path, handler, { times? })` answers matching requests. Paths are matched without the API version; `:name` captures a segment and `*` matches any one; a RegExp with named groups also works. The newest route wins. A handler returns a `Response`, any JSON value (status 200), or `undefined` to fall through to the next route and finally the default. `on()` returns a function that removes the route.

```typescript
import { createMockCloudApi } from 'meta-cloud-api/testing';

const api = createMockCloudApi().install();

api.on('GET', '/:phoneNumberId', ({ params }) => ({
    id: params.phoneNumberId,
    display_phone_number: '+1 555 010 0000',
    verified_name: 'Test Shop',
    quality_rating: 'GREEN',
}));

// Fail only the first send
api.on('POST', '/:phoneNumberId/messages', () => new Response('upstream down', { status: 503 }), { times: 1 });
```

### Errors

`mock.fail(method, path, error, { status?, times? })` replies with Meta's error shape, so the SDK throws the same `WhatsAppError` subclass it would in production. The status defaults to 401 for auth codes, 429 for rate limits and 400 otherwise. `createMetaErrorResponse(error, status?)` builds the `Response` for use inside your own handlers.

```typescript
import { WhatsApp, WhatsAppAuthorizationError, WhatsAppSendMessageError } from 'meta-cloud-api';
import { createMockCloudApi } from 'meta-cloud-api/testing';
import { expect } from 'vitest';

const api = createMockCloudApi().install();
const wa = new WhatsApp({ accessToken: 'test-token', phoneNumberId: 1, retry: { maxAttempts: 1 } });

api.fail('POST', '/:phoneNumberId/messages', { code: 190, message: 'Invalid OAuth access token' });
await expect(wa.messages.text({ to: '15551234567', body: 'hi' })).rejects.toBeInstanceOf(WhatsAppAuthorizationError);

api.reset();
api.fail('POST', '/:phoneNumberId/messages', { code: 131026, message: 'Message undeliverable' });
await expect(wa.messages.text({ to: '15551234567', body: 'hi' })).rejects.toBeInstanceOf(WhatsAppSendMessageError);
```

<Aside type="caution">
The SDK retries rate-limit errors (`WhatsAppThrottlingError`) with backoff, three attempts by default. Pass `retry: { maxAttempts: 1 }` to the client in tests that force throttling errors, or use fake timers.
</Aside>

## Tips

- The SDK looks up `globalThis.fetch` on every request, so clients created before `install()` are intercepted too.
- Run tests that install the mock serially within a file (the Vitest default); `globalThis.fetch` is shared by the whole worker.
- For Jest, the same code works in the default `node` environment on Node.js 20+, which provides `fetch`, `Request` and Web Crypto globally.
- Unit-test pure helpers (`extractMessageText`, `getInteractiveReply`, `isTextMessage`, ...) by passing them `payload.entry[0]?.changes[0]?.value.messages[0]` from a factory.
